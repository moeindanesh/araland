# آرا‌لند — برنامه محصول و اجرا

تاریخ: ۶ سپتامبر ۲۰۲۶. وضعیت: اجرای نسخه اولیه قابل اجرا در محیط توسعه.

## مسئله و جهت محصول

کسب‌وکار کوچک باید بتواند بدون دانش فنی از روی گوشی یک سایت حرفه‌ای راه‌اندازی کند، فرم و محتوایش را عوض کند، مخاطبانش را بشناسد و فایل اختصاصی به آن‌ها تحویل دهد. مزیت پیشنهادی: مدیریت موبایلی، کیفیت طراحی، تجربه فارسی و یک مسیر پیوسته از بازدید تا ارتباط با مشتری.

## محدوده نسخه اول

- ورود مالک و مخاطب با شماره موبایل و کد یک‌بارمصرف؛ در توسعه کد آزمایشی به‌وضوح مشخص است. ارسال واقعی به اعتبار سرویس پیامک نیاز دارد.
- ساخت چند سایت، انتخاب سه قالب، ویرایش بخش‌ها، مرتب‌سازی، نمایش/پنهان‌سازی، پیش‌نویس و انتشار نسخه مستقل.
- فرم ساز با فیلدهای قابل تعریف، ثبت پاسخ و مدیریت مخاطبان هر سایت.
- پنل مخاطب و فایل خصوصی با کنترل دسترسی در سرور.
- بلاگ، FAQ، استوری و محتوای اینستاگرام؛ برای اینستاگرام از پیوند/Embed استفاده می‌شود و اتصال API مستقل است.
- ثبت دامنه و اثبات مالکیت DNS. صدور TLS و تنظیم edge در استقرار انجام می‌شود.
- تولید تصویر با سرویس AI قابل پیکربندی، کتابخانه رسانه و بهینه‌سازی تصویر.
- داشبورد، آمار پایه، وضعیت انتشار و تنظیمات SEO.

## قالب‌ها و تجربه طراحی

۱. **مدار / Orbit**: استودیو خلاق و خدمات حرفه‌ای. زمینه کرم، تایپوگرافی درشت، سبز جنگلی، پروژه‌های تصویری و CTA رزرو مشاوره.
۲. **آرام / Bloom**: زیبایی و سلامت. رنگ زیتونی و صورتی خاکی، تصاویر نرم، خدمات، معرفی متخصص، استوری، FAQ و رزرو.
۳. **فردا / Forma**: آموزش و مشاوره. زمینه سرمه‌ای تیره، لیمویی روشن، کارت دوره‌ها، اعتماد اجتماعی و دریافت مشاوره.

همه قالب‌ها پاسخ‌گو، RTL، دارای بخش‌های مستقل و متکی بر یک schema مشترک هستند. طرح‌ها اصیل‌اند؛ تحقیق برای الگوهای تجربه و کیفیت بصری است.

## معماری

مونوریپو Bun workspaces: `apps/api` (Elysia)، `apps/web` (Next.js App Router + React + CSS)، `apps/mobile` (Expo React Native + HeroUI Native)، `packages/db` (Prisma/PostgreSQL)، `packages/shared` (قراردادهای TypeScript و قالب‌ها).

Next.js برای صفحات عمومی قابل ایندکس، متادیتا و رندر سرور انتخاب می‌شود. اپ بومی با HeroUI Native مستقل از وب است؛ استفاده از کامپوننت DOM در React Native انجام نمی‌شود.

داده‌ها: User → Membership → Workspace → Site؛ Site دارای draft و published، فرم‌ها، ارسال فرم، اعضای مخاطب، فایل‌ها، مقاله‌ها، دامنه‌ها، رسانه و رویدادهای بازدید است. تمام عملیات مدیریت، مالکیت workspace را در سرور بررسی می‌کنند. مخاطب فقط فایل‌های تخصیص‌یافته به هویت خود در همان سایت را می‌بیند.

OTP دارای انقضا، سقف تلاش، محدودیت درخواست و ذخیره هش است. نشست با توکن تصادفی امن و انقضای سروری کنترل می‌شود. فایل خصوصی از endpoint دارای مجوز خوانده می‌شود؛ نام مسیر فایل از کاربر پذیرفته نمی‌شود. سایت عمومی فقط snapshot منتشرشده را دریافت می‌کند.

## ترتیب اجرا و معیار پذیرش

۱. تحقیق رقبا و مستند تصمیم‌ها؛ قرارداد داده و scaffold مونوریپو.
۲. پایگاه‌داده، API و احراز هویت؛ آزمون ورود، جداسازی سایت‌ها و انتشار.
۳. وب فارسی: داشبورد، گالری سه قالب، ویرایشگر، فرم/مخاطب/محتوا/دامنه و پنل مخاطب.
۴. اپ موبایل: ورود، فهرست سایت، ویرایش بخش‌ها، انتخاب قالب، انتشار و مخاطبان.
۵. اتصال یکپارچه، اجرای PostgreSQL محلی، build/typecheck، آزمون API و بررسی واقعی رابط در مرورگر.
۶. README، متغیرهای محیطی، راه‌اندازی و محدودیت‌های استقرار.

معیارها: هر سه قالب قابل مشاهده و فعال‌سازی باشند؛ تغییر draft تا انتشار روی سایت زنده اثر نگذارد؛ یک فرم عمومی پاسخ ثبت کند؛ مخاطب فایل مجاز خودش را بخواند؛ مالک دیگری به سایت دسترسی نداشته باشد؛ اپ بومی typecheck شود؛ وب build شود.

## مسیر پس از نسخه اولیه

پرداخت و اشتراک، نقش‌های تیمی، تاریخچه و rollback، زمان‌بندی محتوا، اتصال CRM، analytics با حفظ حریم خصوصی، آزمون A/B، چندزبانه، accessibility audit، پشتیبان‌گیری و مانیتورینگ، صف پردازش رسانه، storage سازگار S3 و CDN، domain/TLS provisioning، تکمیل تست واقعی iOS/Android و انتشار فروشگاهی. این موارد بدون اجرای واقعی به عنوان تکمیل‌شده گزارش نمی‌شوند.

## وابستگی‌های خارج از محیط

ارسال واقعی پیامک، تولید تصویر پولی، مالکیت دامنه، TLS عمومی و انتشار در فروشگاه‌های موبایل به حساب، اعتبار یا تنظیمات کاربر نیاز دارد. اتصال‌ها با متغیر محیطی آماده می‌شوند؛ تا آن زمان محیط توسعه به‌صراحت آزمایشی باقی می‌ماند.
