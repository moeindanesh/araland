# بازبینی UX و UI پنل آرالند

تاریخ: ۶ سپتامبر ۲۰۲۶. هدف: روشن‌بودن قدم بعدی، حفظ تغییرات کاربر و یکپارچگی مسیر ساخت سایت تا ارتباط با مخاطب. ظاهر سبز و روشن، HeroUI، فونت IRANYekanXFaNum و سایدبار تمام‌عرض حفظ شدند.

## نتیجه و اصلاح‌های اصلی

- داشبورد کاربر واقعی بر اساس وضعیت سایت، «آماده‌سازی و انتشار» یا «مشاهده و پیگیری مخاطبان» را پیشنهاد می‌دهد. پیشرفت از رویدادهای قابل سنجش ساخته می‌شود: ایجاد سایت، انتشار و دریافت اولین پاسخ. دامنه اختصاصی اختیاری است.
- بارگذاری، خطا و عدد صفر آمار از هم جدا هستند. خطای دریافت، آمار صفر نمی‌سازد؛ تلاش دوباره وجود دارد. اعلان ساختگی و علامت انتخاب بازه بدون عملکرد حذف شدند.
- ساخت سایت، آدرس نهایی و ثابت‌بودن آدرس پیش‌فرض را توضیح می‌دهد. قالب انتخاب‌شده وضعیت دسترس‌پذیر دارد؛ هنگام ایجاد، کنترل‌ها و بستن پنجره از درخواست تکراری جلوگیری می‌کنند.
- تغییر قالب قبل از جایگزینی پیش‌نویس تایید می‌گیرد. انتخاب دوباره قالب فعال، تصادفاً محتوا را پاک نمی‌کند. نسخه عمومی تا انتشار بعدی حفظ می‌شود.
- «ذخیره پیش‌نویس» و «انتشار» وضعیت و پیام جدا دارند. اگر ذخیره موفق ولی انتشار ناموفق باشد، پیش‌نویس ذخیره‌شده باقی می‌ماند و راه تلاش دوباره روشن است. پیش از انتشار، آدرس و بخش‌های قابل نمایش مرور می‌شوند.
- پیش‌نمایش ویرایشگر فرم‌های واقعی و نوشته‌های منتشرشده همان سایت را دریافت می‌کند. پیام آمادگی بین پیش‌نمایش و ویرایشگر، مشکل از دست رفتن اطلاعات هنگام بارگذاری اولیه را برطرف می‌کند. به‌روزرسانی منابع و خطای دریافت در دسترس‌اند؛ فرم پیش‌نمایش پاسخ واقعی ثبت نمی‌کند.
- انتخاب بخش، افزودن آیتم و خطای ورودی، فوکوس را به کنترل مربوط می‌برند. حذف آیتم/بخش تایید دارد؛ بخش پنهان راه آشکار برای نمایش دوباره دارد. پیش‌نمایش موبایل و دسترسی به سایت منتشرشده از پنل ویرایشگر هم ممکن‌اند.
- تغییرات تنظیمات، فرم و نوشته در خروج، تعویض بخش، تعویض سایت و بستن پنجره محافظت می‌شوند. Back مرورگر با حفظ مسیر و پیش‌نویس بررسی و اصلاح شد. جستجوی بخش‌ها با Enter و انتخاب نتیجه با کیبورد کار می‌کند.
- پیام‌ها، اعضای ثبت‌نام‌کرده و فایل اختصاصی از هم تفکیک شده‌اند. جستجوی شماره فارسی/عربی، پاک‌کردن جستجو، تازه‌سازی، CSV با عنوان اصلی پرسش‌ها و راهنمای حالت خالی اضافه یا اصلاح شدند.
- فرم‌ها و نوشته‌ها اثر انتشار مستقل خود را توضیح می‌دهند. فایل، وضعیت تحویل به پنل را از ارسال پیامک جدا می‌کند. کپی آدرس سایت و پیوند ورود مخاطب، قدم اشتراک‌گذاری را مستقیم می‌کنند.
- وضعیت دامنه فقط مالکیت TXT را بیان می‌کند؛ اتصال سرور و HTTPS مرحله جداست. بازخورد کنار رکورد مربوط نمایش داده می‌شود. بارگذاری تصویر، تولید AI و خطاهایشان وضعیت مستقل دارند.
- اعتبار کد ورود و ارسال مجدد با ساعت واقعی هماهنگ‌اند. شماره/کد فارسی، ویرایش شماره، خطای کد، انقضا و خطای شبکه مسیر بازیابی روشن دارند. نشست مدیر و مخاطب جدا می‌مانند و مسیر بازگشت به همان مبدأ محدود است.
- متن‌های راهنما، وضعیت‌ها و محدوده لمس موبایل خواناتر و بزرگ‌تر شدند. در گوشی ابتدا ابزار ویرایش در دسترس است و دکمه رفتن به پیش‌نمایش وجود دارد. شکست شبکه در پنل با پیام فارسی قابل تلاش مجدد نمایش داده می‌شود.

## مسیرهای پذیرش و شواهد

| مسیر کاربر | آزمون انجام‌شده | نتیجه |
| --- | --- | --- |
| حساب تازه → سایت | ورود با OTP توسعه، ساخت دو سایت با قالب متفاوت، آدرس پیش‌فرض و حالت پیش‌نویس | موفق |
| مسیریابی و حفظ تغییرات | تنظیمات، بازگرداندن مقدار اولیه، انصراف از خروج، Back و خروج بدون ذخیره | موفق |
| تعویض سایت | انتخاب با Enter/Home، انصراف و تایید خروج از تنظیمات سایت دوم | موفق؛ داده سایت اول درست نمایش داده شد |
| طراحی → انتشار | تغییر عنوان، ورودی تصویر نامعتبر و فوکوس خطا، پیش‌نمایش، انتشار ناموفق شبیه‌سازی‌شده و تلاش دوباره | موفق؛ انتشار ناموفق سایت را عمومی نکرد |
| رسانه → طراحی | بارگذاری PNG، تبدیل به WebP، کپی نشانی و ذخیره در پیش‌نویس | موفق؛ snapshot عمومی بدون انتشار تغییر نکرد |
| پیش‌نمایش تازه | سه بار بازکردن مستقل ویرایشگر و مشاهده نوشته منتشرشده؛ نمایش فرم سفارشی | موفق |
| قالب | بستن تایید با Escape، فعال‌سازی قالب جدید و بررسی API عمومی | موفق؛ قالب عمومی قبلی حفظ شد |
| فرم → پاسخ → مدیریت | ساخت فرم انتخابی با کیبورد، ذخیره کند، ارسال فرم عمومی، جستجوی شماره و CSV | موفق؛ برچسب «نام متقاضی» و پاسخ یکسان بودند |
| نوشته | ایجاد پیش‌نویس بدون جلد، Escape و ادامه ویرایش، انتشار و مشاهده صفحه عمومی و پیش‌نمایش | موفق |
| فایل → مخاطب | ارسال با شماره فارسی، دریافت مالک، ورود مخاطب با کد اشتباه و سپس صحیح، دریافت فایل | موفق؛ هر دو فایل با اصل تطبیق باینری داشتند و نشست‌ها جدا بودند |
| دامنه | ثبت دامنه رزروشده آزمایشی `.invalid`، کپی TXT و بررسی ناموفق رکورد | موفق؛ وضعیت تایید/اتصال ساختگی نمایش داده نشد |
| آمار و شبکه | خطای آمار، نمایش چهار خط تیره، تلاش دوباره؛ قطع شبکه فهرست فرم‌ها و بازیابی | موفق |
| ورود در خطا | شماره نامعتبر، محدودیت ارسال بعد از ویرایش شماره، انقضای کد و قطع شبکه با پاسخ/ساعت کنترل‌شده مرورگر | موفق؛ این موارد آزمون UI شبیه‌سازی‌شده‌اند |
| نشست منقضی‌شده | پاسخ ۴۰۱ کنترل‌شده در نسخه production، پیام انقضا و لینک «ورود دوباره به حساب» تا فرم شماره موبایل | موفق؛ نشست آزمایشی مرورگر پس از بررسی پاک شد |
| کیبورد و منوی گوشی | ۲۴ بار Tab در منو، ۱۲ بار Tab در راهنمای روی آن، Escape و بازگشت فوکوس؛ منوی بسته خارج از فوکوس | موفق |
| پنجره فرم و کنترل‌ها | ۱۲ بار Tab در تایید بستن، Checkbox با Space، نوع فیلد با End/Enter | موفق |
| چیدمان | ۹ بخش × عرض‌های ۳۶۰، ۳۹۰ و ۱۴۴۰، با داده‌های آزمون | ۲۷ ترکیب بدون اسکرول افقی؛ همه آیتم‌های سایدبار هم‌عرض مسیر خود |
| نسخه ساخته‌شده | اجرای production روی IPv4 محلی، دسکتاپ ۱۴۴۰ و گوشی ۳۹۰، پنجره راهنما و فونت | موفق؛ خطای JavaScript مشاهده نشد |

تصاویر و خروجی‌های محلی بررسی در `output/playwright/ux-*` هستند و وارد Git نمی‌شوند. خطاهای شبکه/انتشار/AI عمداً تزریق‌شده در کنسول، از خطای اجرای JavaScript تفکیک شدند.

## بررسی فنی نهایی

`bun run db:generate` و `bun run db:deploy` موفق؛ سه migration موجود و بدون مورد معوق. `bun run typecheck` برای هر پنج workspace موفق. `bun run test` شامل ۱۸ تست و ۱۳۷ assertion موفق روی PostgreSQL واقعی. `bun run build` موفق. API و schema در این بازبینی تغییر نکردند و تغییری در اپ بومی داده نشد.

داده‌های این آزمون شامل دو سایت، دو حساب اختصاصی، فرم‌ها، پاسخ، نوشته، دامنه رزروشده و فایل/رسانه موقت پاک شدند. فایل‌های ذخیره‌شده اختصاصی آزمون هم حذف شدند. هویت، نام، وضعیت و زمان تغییر سایت seed قبل/بعد مقایسه و حفظ شدند.

## مرز تایید و ادامه محصول

این گزارش تایید مسیرهای بررسی‌شده است؛ تضمین نبود هر خطای ممکن یا آزمون کاربری با صاحبان واقعی کسب‌وکار نیست. تست با چند کسب‌وکار واقعی برای سنجش فهم اصطلاحات و نرخ تکمیل مسیر، گام بعدی پایلوت است.

- ارسال پیامک واقعی، تولید تصویر با سرویس دارای اعتبار، اتصال DNS/HTTPS عمومی و اپ روی دستگاه واقعی در این بازبینی اجرا نشدند. خطاها و وضعیت نبود سرویس پوشش داده شدند.
- فهرست‌های API سقف ۱۰۰۰ رکورد دارند؛ رابط آن را آشکار می‌کند. صفحه‌بندی، لغو دسترسی فایل، حذف رسانه/دامنه و نقش‌های تیمی همچنان نیاز توسعه محصول‌اند؛ کنترل نمایشی برای عملیات ناموجود اضافه نشده است.
- رفتار کیبورد و برچسب‌های دسترس‌پذیری بررسی شدند؛ آزمون مستقیم با VoiceOver/NVDA و دستگاه‌های واقعی Android/iOS در این گزارش ادعا نمی‌شود.
