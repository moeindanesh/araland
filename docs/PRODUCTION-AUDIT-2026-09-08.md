# بازبینی آمادگی انتشار — ۸ سپتامبر ۲۰۲۶

## نتیجه

این نسخه برای ادامه پایلوت محلی تقویت شد؛ تأیید بی‌قیدوشرط production صادر نمی‌شود. پیامک واقعی و AI محصول پیکربندی نشده‌اند، ورود توسعه روشن است، دامنه/TLS عمومی و بازیابی backup در این محیط آزمون نشده‌اند. build و export جای آزمون دستگاه واقعی یا استقرار عملیاتی نیستند. «بدون هیچ حالت مرزی» تضمین قابل اثباتی نیست؛ موارد واقعاً بررسی‌شده در زیر ثبت شده‌اند.

بررسی روی تغییرات ثبت‌نشده قبلیِ قابلیت چندصفحه‌ای انجام شد و آن تغییرات حفظ شدند. داده، فرم، فایل و سایت آزمایشیِ این دور اختصاصی‌اند؛ داده seed یا کار کاربر برای آزمون حذف یا بازنویسی نشد.

## دو قالب افزوده‌شده

- **تپش / Pulse**: ورزش و سلامت؛ زمینه تیره، لیمویی، تیتر درشت، عکس حرکت و کارت‌های خدمات. [پیش‌نمایش محلی](http://localhost:3000/preview/pulse).
- **روشا / Luma**: پزشکی و زیبایی؛ سفید مایل به سبز، آبی عمیق، پرتره با بافت طبیعی، خدمات به شکل ردیف‌های خوانا و محتوای روشن درباره درخواست تماس. [پیش‌نمایش محلی](http://localhost:3000/preview/luma).

هر دو از مدل بخش‌های مشترک استفاده می‌کنند؛ متن، تصویر، CTA، خدمات، ترتیب و وضعیت بخش‌ها قابل ویرایش‌اند و با صفحه‌های مستقل، فرم، مقاله و منوی موجود کار می‌کنند. انتخاب در پنل وب، ساخت سایت، ویرایشگر و اپ بومی اضافه شده است. تصویرسازی قالب با ابزار داخلی Imagegen انجام شد و ارتباطی با فعال‌بودن سرویس AI داخل محصول ندارد.

## بررسی فنی و پایگاه‌داده

- `db:generate` موفق.
- خطای P3005 محیط موجود بررسی شد. سه migration روی schema اختصاصی تازه اعمال و نتیجه با مدل Prisma تطبیق داده شد. ساختار موجود نیز با همان مدل بدون اختلاف بود. پس از این دو تطبیق، سه migration موجود به‌عنوان applied ثبت شدند؛ جدول و داده موجود migrate یا reset نشدند. مقایسه سایت‌ها، پیش‌نویس‌ها، snapshotها و زمان‌ها قبل/بعد یکسان بود.
- `db:deploy` محیط موجود پس از baseline موفق و بدون migration معوق است. schema آزمایشی پاک شد.
- آزمون API روی schema تازه: ۲۴ آزمون و ۲۴۵ assertion در زمان اجرای آن مرحله، همگی موفق.
- `typecheck` همه workspaceها، تست‌های API/وب، build وب و `mobile:export` موفق شدند: ۲۵ آزمون API با ۲۶۱ assertion و ۱۲ آزمون وب با ۳۷ assertion؛ مجموع ۳۷ آزمون و ۲۹۸ assertion بدون شکست.
- ۹ بخش پنل × ۲ عرض: ۱۸ ترکیب بدون اسکرول افقی یا pageerror. پنج قالب × ۲ عرض: ۱۰ ترکیب، منو/FAQ/استوری با کیبورد موفق. ویرایشگر در هر دو عرض بررسی شد.
- نسخه ساخته‌شده با Next start روی پورت ۳۱۰۰ برای ۱۱ مسیر HTTP شامل هر پنج قالب، صفحه عمومی، نقشه سایت و robots پاسخ ۲۰۰ داد. این مرحله تأیید تنظیم CORS روی یک دامنه استقرار واقعی نیست.
- چهار مسیر ناموجود (قالب، سایت، صفحه داخلی و پنل مخاطب) در نسخه production پاسخ ۴۰۴ دادند. هدر noindex در ورود، ویرایشگر، پیش‌نمایش و پنل مخاطب بررسی شد. فیلتر ورزشی با Enter و فیلتر پزشکی با کلیک فقط قالب مربوط را نمایش دادند؛ انتخاب Pulse پس از ورود واقعی با OTP توسعه حفظ شد.
- Expo Go 57.0.9 روی iPhone 16 Pro / iOS 18.5 با Metro فعلی اجرا و پس از بستن process دوباره باز شد. صفحه آغاز و فونت در هر دو اجرا دیده شدند و خطای `ExpoAsset` در این دو شروع دیده نشد؛ رفع قطعی خطای reload ثبت‌شده در README موبایل از این مشاهده نتیجه نمی‌شود. پنجره معرفی Expo Go جلوی بخشی از رابط بود و Simulator در ابزار کنترل رابط در دسترس نبود، بنابراین ورود و اکشن‌های اپ با تعامل واقعی تأیید نشدند. شبیه‌ساز و Metro اختصاصی این آزمون بعداً متوقف شدند.

اسکرین‌شات‌ها و harness محلی در `output/playwright/` هستند و وارد Git نمی‌شوند. شکست‌های مقطعی حین HMR و شکست selectorهای harness با خطای محصول مخلوط نشده‌اند.

در پایان، workspace، سایت، فرم‌ها، لید، عضویت و نشست‌های حساب اختصاصی این آزمون پاک شدند؛ فایل آزمایشی قبلاً از رابط لغو و از storage حذف شده بود. تطبیق تراکنشی تأیید کرد سایت باقی‌مانده و همه فیلدهای آن تغییری نکردند. فایل‌های محلی حاوی توکن آزمون نیز حذف شدند. پیش‌نمایش دو قالب مستقل از این fixture باقی می‌ماند.

حذف فایل، دریافت‌های آینده را می‌بندد؛ نسخه دانلودشده پیشین یا دانلودی که قبل از لغو آغاز شده قابل پس‌گرفتن نیست. اگر storage هنگام حذف خطا دهد، مجوز دریافت قبلاً حذف شده و رخداد cleanup ثبت می‌شود؛ مدیریت فایل orphan جزو کار عملیاتی باقی‌مانده است.

قالب پزشکی برای معرفی خدمات و درخواست تماس است؛ ادعای سامانه پرونده پزشکی، تشخیص، حفظ داده بالینی مطابق یک استاندارد مشخص یا رزرو قطعی ندارد. معرفی متخصص، شماره مجوز، آدرس و هزینه واقعی باید توسط صاحب کسب‌وکار تکمیل شود.
