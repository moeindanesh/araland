# آرالند · Araland

خانه دیجیتال کسب‌وکار، با مدیریت از گوشی. یک مونوریپوی واقعی با وب فارسی و RTL، اپ بومی مدیریت و API چندمستاجری.

**وضعیت:** نسخه اولیه قابل اجرا در توسعه؛ وب و سرور و اپ پیاده شده‌اند. سرویس‌های پولی و استقرار عمومی هنوز به تنظیم حساب‌ها نیاز دارند. این پروژه نسخه منتشرشده در فروشگاه‌های موبایل نیست.

## همین حالا ببینید

- پنل وب: [localhost:3000](http://localhost:3000)
- قالب معماری و استودیو «مدار»: [Orbit](http://localhost:3000/preview/orbit)
- قالب زیبایی و سلامت «آرام»: [Bloom](http://localhost:3000/preview/bloom)
- قالب آموزش و مشاوره «فردا»: [Forma](http://localhost:3000/preview/forma)
- قالب ورزش و سلامت «تپش»: [Pulse](http://localhost:3000/preview/pulse)
- قالب پزشکی و زیبایی «روشا»: [Luma](http://localhost:3000/preview/luma)
- سایت منتشرشده نمونه: [استودیو مدار](http://localhost:3000/s/madar-studio)
- پنل فایل مخاطب: [پنل اختصاصی](http://localhost:3000/portal/madar-studio)

داشبورد قبل از ورود به‌وضوح یک فضای نمونه است. برای ورود به داده‌های seed شماره `09121234567` را وارد کنید. در حالت توسعه یک کد تصادفی همان درخواست در صفحه نشان داده می‌شود؛ کد ثابت و راه میان‌بر احراز هویت وجود ندارد. برای کسب‌وکار مستقل، با شماره دیگری وارد شوید و سایت بسازید.

## اجرا

نیازمندی‌ها: Bun 1.3+ و PostgreSQL 17 یا Docker. در این محیط PostgreSQL جداگانه روی پورت `55432` راه‌اندازی شده است.

```sh
bun install
cp .env.example .env
cp apps/web/.env.example apps/web/.env.local
bun run db:local
bun run db:generate
bun run db:deploy
bun run db:seed
bun run dev
```

اگر ابزار PostgreSQL محلی نصب نیست، به‌جای `db:local` از `docker compose up -d postgres` استفاده کنید. این دو روش را هم‌زمان روی پورت یکسان اجرا نکنید. راه‌انداز محلی پوشه اختصاصی `.data/postgres` می‌سازد و فقط روی `127.0.0.1` گوش می‌دهد. مسیر ابزارها با `PG_BIN` قابل تعیین است. توقف همان پایگاه‌داده: `bun run db:stop`.

وب روی `3000` و API روی `4000` اجرا می‌شوند. `db:deploy` migration نسخه‌بندی‌شده را اعمال می‌کند؛ `db:push` صرفاً میان‌بر توسعه است. پوشه‌های `.data` و `.storage` و فایل‌های `.env` در Git ثبت نمی‌شوند.

### اپ مدیریت

```sh
cp apps/mobile/.env.example apps/mobile/.env
bun run dev:mobile
```

از Expo SDK 57، React Native 0.86.3 و HeroUI Native استفاده شده است. برای گوشی فیزیکی، `EXPO_PUBLIC_API_URL` را به IP شبکه کامپیوتر و پورت ۴۰۰۰ تغییر دهید. برای نمایش تصاویر روی گوشی `API_PUBLIC_URL` سرور هم باید همان IP شبکه باشد. اپ برای iOS و Android است؛ رابط وب مستقل با Next.js ساخته شده است. [راهنمای کامل اپ](apps/mobile/README.md).

پنل وب از **HeroUI 3** برای دکمه‌ها، ورودی‌ها، انتخاب‌گرها، تیک‌ها، تب‌ها، کارت‌های مدیریت و پنجره‌ها استفاده می‌کند؛ ظاهر سبز و روشن فعلی حفظ شده است. فونت پنل و اپ **IRANYekanX با اعداد فارسی** از بسته ارائه‌شده شماست و به‌صورت محلی همراه پروژه قرار دارد. [جزئیات منابع](docs/ASSETS.md).

**فرم‌ها و مقاله‌ها منابع مستقل هستند:** انتشار/ویرایش آن‌ها مستقیم روی سایت منتشرشده اثر می‌گذارد. snapshot انتشار مخصوص ساختار صفحه، قالب، نام و SEO است.

**مدیریت صفحه‌ها:** در ویرایشگر سایت، تب «صفحه‌ها و منوها» را باز کنید. صفحهٔ عمومی، خدمت یا موضوع بسازید، از انتخاب‌گر «صفحهٔ در حال ویرایش» محتوای هر صفحه را تغییر دهید و لینک‌های منوی بالا و پایین را جدا تنظیم کنید. در کارت خدمات نیز «ساخت صفحه برای این خدمت یا موضوع» صفحه را ایجاد و به کارت وصل می‌کند. لینک انتخاب‌شده به شناسهٔ صفحه متصل است و تغییر آدرس را دنبال می‌کند. فعال‌بودن صفحه با نمایش آن در منو متفاوت است؛ صفحهٔ فعال بدون منو هم با لینک مستقیم قابل دسترس است. ذخیره و انتشار شامل همهٔ صفحه‌ها و منوهاست. [برنامه و معیارهای پذیرش](docs/MULTI-PAGE-PLAN.md).

**اینستاگرام:** در نسخه اول تصویر و لینک پست به انتخاب مالک ثبت می‌شود. همگام‌سازی خودکار حساب Instagram هنوز پیاده نشده است.

## معماری و تصمیم‌ها

```text
apps/web       Next.js 16 + React 19 + HeroUI 3 · داشبورد و رندر سروری صفحات عمومی
apps/api       Bun + Elysia · احراز هویت و تمام کنترل دسترسی
apps/mobile    Expo + React Native + HeroUI Native · اپ مدیریت فارسی
packages/db    Prisma + PostgreSQL · schema و migration و seed
packages/shared TypeScript · قراردادها، قالب‌ها و client
```

Next.js برای قابلیت ایندکس و متادیتای صفحات عمومی انتخاب شده است. هویت دسترسی در API بررسی می‌شود؛ شناسه سایتی که کلاینت می‌فرستد به‌تنهایی مجوز نیست. فایل خصوصی خارج از مسیر static ذخیره و با مجوز دریافت می‌شود. نشست وب در مرورگر و نشست موبایل در SecureStore نگهداری می‌شود؛ برای سخت‌سازی بعدی وب، cookie دارای HttpOnly و لایه BFF در نقشه راه است.

## بررسی‌ها

```sh
bun run typecheck
bun run test
bun run build
bun run mobile:export
```

آزمون‌های سرور با PostgreSQL واقعی اجرا می‌شوند و هویت‌ها، سایت‌ها و فایل‌های اختصاصی آزمایش را پس از پایان پاک می‌کنند. این تست‌ها پیامک واقعی یا درخواست پولی AI نمی‌فرستند. خروجی Native export یک bundle قابل اجراست؛ جای build امضاشده و آزمون تعاملی دستگاه را نمی‌گیرد.

## برای استفاده عمومی چه چیزهایی لازم است؟

۱. تنظیم سرویس پیامک کاوه‌نگار و قالب تاییدشده؛ خاموش‌کردن `AUTH_DEV_MODE` و قراردادن `AUTH_SECRET` تصادفی خصوصی.
۲. تنظیم اعتبار `OPENAI_API_KEY` در سرور برای تصویرسازی. بدون آن پیام روشن «سرویس پیکربندی نشده» می‌آید.
۳. سرور عمومی، دامنه اصلی، TLS، DNS و storage پایدار. تایید TXT فقط مالکیت دامنه است؛ HTTPS باید در edge تنظیم شود. مقدار TXT دقیق: `araland-verification=TOKEN`.
۴. آزمون iOS/Android روی دستگاه و build امضاشده برای انتشار.
۵. قبل از رشد عمومی: محدودسازی مشترک درخواست بین چند سرور، سهمیه و صف AI، اشتراک/پرداخت، پشتیبان‌گیری، اسکن فایل، مانیتورینگ، صفحه‌بندی فهرست‌ها و بررسی حریم خصوصی.

موارد مرحله بعد با معیار پذیرش در نقشه راه آمده‌اند؛ در این نسخه به‌عنوان تکمیل‌شده نمایش داده نمی‌شوند.
